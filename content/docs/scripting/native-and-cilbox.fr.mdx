Basis exécute du code de deux façons. Celle que vous utilisez dépend de **l'endroit où vit le script** : dans l'application que vous compilez, ou dans du contenu chargé à l'exécution.

## Native : compilé dans l'application

Un script natif est un `MonoBehaviour` Unity ordinaire intégré au client Basis (ou à votre propre application construite sur le framework Basis). Il est compilé avec l'application et livré avec la prochaine compilation du client, et non avec un monde ou un prop.

- C# complet et toute l'API Unity et Basis.
- Vitesse native complète.
- Peut hériter de classes Basis comme `BasisNetworkBehaviour` et `BasisSyncedObject`.
- N'existe que dans les clients compilés avec lui. Les joueurs sur le client public n'ont pas votre script.

Utilisez des scripts natifs lorsque vous **construisez une application ou un jeu sur Basis** : vos propres menus, règles de jeu, systèmes et tout composant dont votre contenu dépend.

## Cilbox : scripts à l'exécution dans le contenu

Un script Cilbox est un `MonoBehaviour` marqué `[Cilboxable]` qui est livré **à l'intérieur** d'un fichier `.bee` de monde, de prop ou d'avatar. Lorsque le contenu se charge, Basis l'exécute dans l'interpréteur Cilbox, à l'intérieur d'une sandbox propre à ce type de contenu (Scene, Prop ou Avatar).

- Fonctionne sur n'importe quel client Basis qui charge le contenu. Aucune compilation du client n'est nécessaire.
- En sandbox. Seuls les types et méthodes de la liste blanche peuvent être appelés, ce qui empêche le contenu de nuire à la machine du joueur.
- Plus lent que le natif, car le code est interprété.
- Utilise des shims au lieu de classes de base, par exemple `BasisNetworkShim` au lieu d'hériter de `BasisNetworkBehaviour`.

Utilisez Cilbox lorsque vous **créez du contenu utilisateur** : des mondes, props et avatars que d'autres personnes chargent.

## En un coup d'œil

| | Native | Cilbox |
| --- | --- | --- |
| Se trouve dans | La compilation de l'application | Le monde, le prop ou l'avatar |
| Chargé | Lors de la compilation de l'application | À l'exécution, avec le contenu |
| Marqué avec | Rien | `[Cilboxable]` |
| API | Tout | Liste blanche par sandbox |
| Vitesse | Native | Interprété, beaucoup plus lent |
| Réseau | Hériter de `BasisNetworkBehaviour` | Utiliser `BasisNetworkShim` |
| Qui l'a | Les joueurs sur votre build | Toute personne qui charge le contenu |

## Le même script des deux façons

```csharp title="Native"
using Basis;
using Basis.Network.Core;

public class Door : BasisNetworkBehaviour
{
    public override void OnNetworkMessage(ushort sender, byte[] buffer, DeliveryMethod method)
    {
        gameObject.SetActive(buffer[0] != 0);
    }
}
```

```csharp title="Cilbox"
using Basis;
using Basis.Network.Core;
using Cilbox;
using UnityEngine;

[Cilboxable]
public class Door : MonoBehaviour
{
    BasisNetworkShim net;

    void Start()
    {
        net = GetComponent<BasisNetworkShim>();
        net.NetworkMessageReceived += OnMessage;
    }

    void OnMessage(ushort sender, byte[] buffer, DeliveryMethod method)
    {
        gameObject.SetActive(buffer[0] != 0);
    }
}
```

## Livrer chacun d'eux

- Native : ajoutez le script à votre projet Unity et compilez le client. Si un composant natif est placé dans un bundle de monde ou de prop, ajoutez aussi son type au sélecteur de content police correspondant, sinon il est supprimé au chargement du contenu (voir [Composants autorisés](/fr/docs/scripting/allowed-components)).
- Cilbox : ajoutez un **Cilbox Scene Basis** (monde) ou un **Cilbox Prop Basis** (prop) à votre contenu, marquez les scripts `[Cilboxable]` et compilez le `.bee` comme d'habitude. Voir [Bases](/fr/docs/scripting/examples/basics).

<Callout type="info">
Les exemples de cette documentation sont étiquetés **Native** ou **Cilbox**. La plupart des exemples Cilbox se compilent aussi comme scripts natifs ; les exemples natifs nécessitent généralement des modifications pour fonctionner dans Cilbox. Les règles à surveiller se trouvent dans [Règles de la sandbox](/fr/docs/scripting/sandbox-rules).
</Callout>
