`BasisSaveShim` speichert Bytes auf dem Rechner des Spielers, abgelegt unter der ID Ihres Inhalts. Es gilt pro Spieler: Jeder Spieler hat seinen eigenen Speicherstand, und nichts wird synchronisiert.

## Skript

Dieses Skript speichert, welche Checkpoints ein Spieler erreicht hat, und seine Bestzeit, und setzt ihn bei seiner Rückkehr an seinen letzten Checkpoint zurück.

```csharp title="CourseProgress.cs (Cilbox)"
using System.IO;
using Basis.Scripts.BasisSdk.Players;
using Basis.Shims;
using Cilbox;
using TMPro;
using UnityEngine;

[Cilboxable]
public class CourseProgress : MonoBehaviour
{
    const string Slot = "progress";
    const byte Version = 1;

    public Transform[] checkpoints;
    public TextMeshPro bestLabel;

    int reached = -1;
    float bestTime = float.MaxValue;

    void Start()
    {
        Load();
        if (reached >= 0)
        {
            Transform point = checkpoints[reached];
            BasisLocalPlayer.Instance.Teleport(point.position, point.rotation, BasisTeleportMode.Instant);
        }
        ShowBest();
    }

    public void ReachCheckpoint(int index)
    {
        if (index <= reached) return;
        reached = index;
        Save();
    }

    public void FinishRun(float seconds)
    {
        if (seconds < bestTime) bestTime = seconds;
        reached = -1;
        Save();
        ShowBest();
    }

    void Save()
    {
        using (var stream = new MemoryStream())
        using (var writer = new BinaryWriter(stream))
        {
            writer.Write(Version);
            writer.Write(reached);
            writer.Write(bestTime);
            BasisSaveShim.Save(this, Slot, stream.ToArray());
        }
    }

    void Load()
    {
        byte[] data = BasisSaveShim.Load(this, Slot);
        if (data == null || data.Length < 9) return;
        using (var reader = new BinaryReader(new MemoryStream(data)))
        {
            if (reader.ReadByte() != Version) return;
            reached = Mathf.Clamp(reader.ReadInt32(), -1, checkpoints.Length - 1);
            bestTime = reader.ReadSingle();
        }
    }

    void ShowBest()
    {
        bestLabel.text = bestTime < float.MaxValue ? $"Best: {bestTime:F1}s" : "No time yet";
    }
}
```

## Regeln

- Der Spieler entscheidet. Bis er das Speichern für Ihren Inhalt erlaubt, gibt `Save` false und `Load` null zurück. Ihr Skript läuft in beiden Fällen weiter. Behandeln Sie immer einen fehlenden Speicherstand.
- Versionieren Sie Ihre Daten. Schreiben Sie zuerst ein Versions-Byte und lehnen Sie Daten ab, die Sie nicht verstehen. Spieler behalten alte Speicherstände, wenn Sie Ihre Welt aktualisieren.
- Beim Laden validieren. Begrenzen Sie Indizes; verlassen Sie sich nie darauf, dass gespeicherte Werte noch zu Ihrer Szene passen.
- Grenzen: 256 KB pro Slot, 32 Slots und 1 MB pro Store, 8 Schreibvorgänge pro Sekunde. Speichern Sie bei wichtigen Ereignissen, nicht in jedem Frame.

## Teilen zwischen Inhalten

Benennen Sie einen Store, um Speicherstände zu teilen, zum Beispiel zwischen einer Welt und den Props, die sie spawnt:

```csharp
BasisSaveShim.Save(this, "my-game", "progress", bytes);
byte[] data = BasisSaveShim.Load(this, "my-game", "progress");
```

Scopes legen fest, wer lesen und schreiben darf:

| Scope | Lesen | Schreiben |
| --- | --- | --- |
| `BasisSaveScope.Protected` | Nur dieser Inhalt | Nur dieser Inhalt |
| `BasisSaveScope.ReadOnly` | Beliebiger Inhalt (mit Ihrer Content ID) | Nur dieser Inhalt |
| `BasisSaveScope.Shared` | Jeder Inhalt, der den Store benennt | Jeder Inhalt, der den Store benennt |

```csharp
// Publish a badge other worlds can read.
BasisSaveShim.Save(this, BasisSaveScope.ReadOnly, null, "badge", bytes);

// Another world reads it.
byte[] badge = BasisSaveShim.LoadReadOnly(this, partnerContentId, null, "badge");
```

<Callout type="warn">
Speicherstände liegen auf dem Rechner des Spielers und können von ihm bearbeitet werden. Verwenden Sie sie nicht für etwas, dem vertraut werden muss, etwa Bestenlisten.
</Callout>
