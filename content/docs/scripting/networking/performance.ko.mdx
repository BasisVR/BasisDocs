## 비용을 낮게 유지하기

- **프레임이 아니라 상태를 보내세요.** 동기화 변수는 값이 바뀔 때만 전송됩니다. `Update`에서 `SendCustomNetworkEvent`를 호출하지 마세요.
- **가장 작은 타입을 사용하세요.** `Int` 대신 `Byte`나 `Bool`, 원본 float 대신 범위 지정 float.
- **높은 빈도의 데이터에는 비신뢰 전송을 사용하세요.** 신뢰형 메시지는 도착할 때까지 재전송되므로, 패킷이 손실되면 비용이 더 들고 지연이 늘어납니다.
- **`DistanceReduction`을 켜 두세요.** 멀리 있는 플레이어는 업데이트를 덜 받습니다. 방 밖의 아무도 볼 필요가 없는 오브젝트에는 `RelevanceCulling`을 켜세요.
- **오브젝트 하나에 여러 값.** 값 10개를 가진 `BasisSyncedParameters` 하나가 값을 하나씩 가진 오브젝트 10개보다 저렴합니다. 각 오브젝트는 자체 헤더와 키프레임을 가지기 때문입니다.
- **이벤트를 일괄 처리하세요.** 변경마다 메시지를 하나씩 보내는 대신 여러 변경을 하나의 메시지에 담으세요.

<Callout type="info">
유휴 상태의 동기화 오브젝트는 비용이 거의 들지 않습니다. 값이 바뀌지 않는 동안에는 아무것도 보내지 않고, 키프레임 간격도 늘어납니다. 피해야 할 비용은 그럴 필요가 없는데도 매 프레임 바뀌는 값입니다.
</Callout>

## 흔한 동기화 버그

| 증상 | 일반적인 원인 |
| --- | --- |
| 나에게는 작동하지만 다른 사람은 아무도 보지 못함 | 변경이 로컬에만 적용되고 전송되지 않았거나, 오브젝트가 아직 네트워크 준비 상태가 아니었습니다(`HasNetworkID`가 false). |
| 늦게 참여한 플레이어가 씬 기본값을 봄 | 상태가 이벤트로 전송되고 `OnPlayerJoined`에서 다시 보내지 않았습니다. [늦게 참여한 플레이어](/ko/docs/scripting/networking/late-joiners)를 참조하세요. |
| 두 플레이어가 값을 두고 다툼 | 둘 다 값을 씁니다. 소유자만 써야 하며, 플레이어가 행동할 때 소유권을 가져오세요. |
| 값을 바꾼 뒤 다시 되돌아감 | 오브젝트를 소유하지 않은 채 동기화 변수를 써서 소유자의 스트림이 덮어썼습니다. |
| 누군가 참여하면 모든 것이 초기화됨 | `Start`나 `OnNetworkReady`에서 소유권을 가져오므로, 새로 온 사람이 기본값을 가진 채 소유자가 됩니다. |
| 이벤트 핸들러가 두 번 호출됨 | `Start`에서 구독하고 `OnEnable`에서 또 구독했거나, `OnDestroy`에서 구독을 해제하지 않았습니다. |

## 도구

- **플레이 모드의 인스펙터.** 동기화 오브젝트, 픽업, 좌석 인스펙터는 소유자, 네트워크 ID, 버퍼 깊이, 초당 바이트를 보여줍니다.
- **동기화 기즈모.** 원격 동기화 오브젝트는 어디에 있었고 어디로 향하는지를 그려서, 보간과 외삽을 한눈에 보여줍니다.
- **여러 클라이언트.** 클라이언트를 빌드하여 에디터 옆에서 실행하고, 둘 다 로컬 서버에 연결하세요. [테스트](/ko/docs/world/testing)를 참조하세요.
- **`BasisStatsShim`**(Cilbox)은 왕복 시간과 마지막 패킷 이후 경과한 초를 알려주므로, "재연결 중" 표시를 보여주는 데 유용합니다.
