스크립트가 하는 모든 일은 한 플레이어의 기기에서 실행됩니다. 플레이어가 문을 열어도 네트워크에 알리기 전까지는 아무도 그것을 보지 못합니다. 이 가이드는 이를 위해 Basis가 제공하는 도구와 각각을 언제 사용해야 하는지 다룹니다.

전송 계층 자체의 작동 방식(서버 릴레이, 전송 방식, 거리 기반 업데이트 빈도)은 [네트워크 동기화](/ko/docs/technical/network-syncing)를 참조하세요.

## 네 가지 개념

| 개념 | 설명 | 용도 |
| --- | --- | --- |
| **동기화 변수** | 소유자가 쓰고 다른 모든 사람이 읽는 값으로, 지속적으로 전송되고 보간됩니다. | 위치, 레버 각도, 점수 등 현재 상태가 있는 모든 것. |
| **네트워크 이벤트** | 바이트 페이로드를 가진 일회성 메시지. | "총이 발사되었다", "라운드가 시작되었다", "이 소리를 재생하라". |
| **소유권** | 각 네트워크 오브젝트는 정확히 한 명의 플레이어가 소유하며, 그 플레이어만 쓸 수 있습니다. | 누가 픽업을 조작할지, 누가 점수를 관리할지 결정. |
| **늦게 참여한 플레이어** | 상황이 바뀐 뒤에 도착한 플레이어. | 씬 기본값이 아니라 현재 상태를 보도록 보장. |

<Callout type="info">
경험 법칙: 5분 뒤에 참여한 플레이어도 봐야 하는 것이라면 그것은 **상태**이며 동기화 변수에 속합니다(또는 그 플레이어에게 다시 보내야 합니다). 일어나는 순간에만 중요하다면 그것은 **이벤트**입니다.
</Callout>

## 구성 요소

- **`BasisNetworkBehaviour`**는 클라이언트에 컴파일되는 네트워크 스크립트의 기본 클래스입니다. 네트워크 ID, 소유자, 그리고 `OnNetworkReady`, `OnNetworkMessage`, `OnOwnershipTransfer`, `OnPlayerJoined`, `OnPlayerLeft` 콜백을 갖습니다.
- **`BasisNetworkShim`**은 Cilbox 스크립트를 위한 같은 기능입니다. Cilbox 스크립트는 `BasisNetworkBehaviour`를 상속할 수 없으므로 `GetComponent`로 `BasisNetworkShim`을 가져와 이벤트를 구독합니다.
- **`BasisSyncedObject`**는 `BasisNetworkBehaviour`를 기반으로 압축되고 보간되는 상태 스트림을 제공합니다. **`BasisSyncedParameters`**, **`BasisSyncedTransform`**, **`BasisSyncedRigidbody`**는 그 위에 만들어진 기성 컴포넌트입니다.
- **`BasisPickupSyncNetworking`**과 **`BasisSeatSync`**는 코드 없이 픽업과 좌석을 동기화합니다.

## 네트워크 스크립트, 처음부터 끝까지

```csharp title="NetworkedCounter.cs (Native)"
using System;
using Basis;
using Basis.Network.Core;
using Basis.Scripts.Networking.NetworkedAvatar;
using TMPro;
using UnityEngine;

public class NetworkedCounter : BasisNetworkBehaviour
{
    public TextMeshPro label;
    int count;

    public void Increment()
    {
        TakeOwnership();
        count++;
        Show();
        SendCustomNetworkEvent(BitConverter.GetBytes(count), DeliveryMethod.ReliableOrdered);
    }

    public override void OnNetworkMessage(ushort playerId, byte[] buffer, DeliveryMethod method)
    {
        if (buffer == null || buffer.Length < 4) return;
        count = BitConverter.ToInt32(buffer, 0);
        Show();
    }

    public override void OnPlayerJoined(BasisNetworkPlayer player)
    {
        if (IsLocalOwner())
        {
            SendCustomNetworkEvent(BitConverter.GetBytes(count), DeliveryMethod.ReliableOrdered, new[] { player.playerId });
        }
    }

    void Show() => label.text = count.ToString();
}
```

이런 Native 스크립트는 클라이언트 빌드에서 작동합니다. 업로드되는 콘텐츠에서는 같은 내용을 Cilbox 스크립트로 작성하세요(아래 참조).

이 예제가 보여주는 것:

1. 버튼을 누른 플레이어가 **소유권을 가져오므로** 신뢰할 수 있는 원본이 하나가 됩니다.
2. 새 값은 다른 모든 사람에게 **이벤트로 전송됩니다**(`Recipients = null`은 자신을 제외한 모든 사람을 의미합니다).
3. 누군가 참여하면 **소유자만** 현재 값을 그 사람에게 보냅니다.

같은 스크립트의 Cilbox 버전은 [네트워크 이벤트](/ko/docs/scripting/networking/network-events#cilbox)에 있습니다.

## 이 가이드의 페이지

- [네트워크 이벤트](/ko/docs/scripting/networking/network-events): 메시지 전송, 수신자, 전송 방식, 페이로드.
- [동기화 변수](/ko/docs/scripting/networking/synced-variables): `BasisSyncedParameters`와 커스텀 `BasisSyncedObject` 필드.
- [소유권](/ko/docs/scripting/networking/ownership): 누가 무엇을 소유하는지, 소유권 가져오기와 확인, 소유자가 떠나면 어떻게 되는지.
- [늦게 참여한 플레이어](/ko/docs/scripting/networking/late-joiners): 새 플레이어를 최신 상태로 맞추기.
- [네트워크 컴포넌트](/ko/docs/scripting/networking/network-components): 코드 없는 동기화 컴포넌트.
- [성능과 디버깅](/ko/docs/scripting/networking/performance): 대역폭, 전송 빈도, 동기화 버그 찾기.
