## 軽く保つ

- フレームではなく状態を送信します。同期変数は値が変わったときにだけ送信されます。`Update`から`SendCustomNetworkEvent`を呼ばないでください。
- 最小の型を使います。`Int`の代わりに`Byte`や`Bool`を、生のfloatの代わりに範囲指定のfloatを使います。
- 高頻度のデータには信頼性のない配信を使います。確実なメッセージは届くまで再送されます。その分コストが高く、パケットが失われると遅延も増えます。
- `DistanceReduction`はオンのままにします。遠くのプレイヤーへの更新は少なくなります。部屋の外の誰にも見える必要のないオブジェクトには`RelevanceCulling`をオンにしてください。
- 多くの値は1つのオブジェクトにまとめます。10個の値を持つ1つの`BasisSyncedParameters`は、値を1つずつ持つ10個のオブジェクトより軽量です。各オブジェクトはそれぞれ独自のヘッダーとキーフレームを持つためです。
- イベントをまとめます。変更ごとに1通のメッセージを送るのではなく、複数の変更を1通のメッセージに詰めてください。

<Callout type="info">
アイドル状態の同期オブジェクトのコストはほぼゼロです。値が変わらない間は何も送信されず、キーフレームの間隔も延びます。避けるべきコストは、必要がないのに毎フレーム変わる値です。
</Callout>

## よくある同期バグ

| 症状 | よくある原因 |
| --- | --- |
| 自分では動くが、他の誰にも見えない | 変更がローカルで適用されただけで送信されていない、またはオブジェクトがまだネットワーク準備完了ではなかった（`HasNetworkID`がfalse）。 |
| 途中参加者にシーンのデフォルトが見える | 状態がイベントとして送信され、`OnPlayerJoined`で再送されていない。[途中参加者](/ja/docs/scripting/networking/late-joiners)を参照してください。 |
| 2人のプレイヤーが値を取り合う | 両方が書き込んでいる。書き込むのはオーナーだけにし、プレイヤーが行動したときにオーナーシップを取得してください。 |
| 変更した後に値が元に戻る | オブジェクトを所有せずに同期変数に書き込んだため、オーナーのストリームに上書きされた。 |
| 誰かが参加するとすべてリセットされる | `Start`または`OnNetworkReady`でオーナーシップを取得しているため、新しく来たプレイヤーがデフォルト値のままオーナーになる。 |
| イベントハンドラーが2回発火する | `Start`で購読し、さらに`OnEnable`でも購読している、または`OnDestroy`で購読解除していない。 |

## ツール

- プレイモードのインスペクター。同期オブジェクト、ピックアップ、座席のインスペクターには、オーナー、ネットワークID、バッファの深さ、1秒あたりのバイト数が表示されます。
- 同期ギズモ。リモートの同期オブジェクトは、どこにいたかとどこへ向かっているかを描画し、補間と外挿の様子をその場で確認できます。
- 複数のクライアント。クライアントをビルドしてエディターと並べて実行し、両方をローカルサーバーに接続します。[Testing](/ja/docs/world/testing)を参照してください。
- `BasisStatsShim`（Cilbox）は往復時間と最後のパケットからの秒数を報告します。「再接続中」の表示に使えます。
