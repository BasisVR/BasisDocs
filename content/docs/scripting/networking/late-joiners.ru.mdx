Подключившийся игрок загружает сцену ровно такой, какой вы её собрали. Всё, что изменилось с тех пор (открылась дверь, вырос счёт, выключили свет), для него невидимо, пока кто-нибудь ему не сообщит.

## Синхронизированные переменные: всё делается за вас

`BasisSyncedObject` и всё, что построено на нём (`BasisSyncedParameters`, `BasisSyncedTransform`, `BasisSyncedRigidbody`, `BasisPickupSyncNetworking`), отправляют полный ключевой кадр каждый раз, когда подключается игрок. Если владелец ушёл и у объекта ещё нет владельца, новичку отправляет состояние игрок, у которого оно есть. Вам ничего делать не нужно.

## Сетевые события: отправьте состояние ещё раз

События не запоминаются. Если событие изменило долговременное состояние, отправьте новому игроку это **состояние** повторно (а не историю событий). Делает это только владелец, поэтому новичок получает одно сообщение, а не по одному от каждого.

```csharp title="Native"
public override void OnPlayerJoined(BasisNetworkPlayer player)
{
    if (!IsLocalOwner()) return;
    SendCustomNetworkEvent(PackState(), DeliveryMethod.ReliableOrdered, new[] { player.playerId });
}
```

```csharp title="Cilbox"
void OnPlayerJoined(BasisNetworkPlayer player)
{
    if (!net.HasNetworkID || !net.IsOwnedLocallyOnServer) return;
    net.SendCustomNetworkEvent(PackState(), DeliveryMethod.ReliableOrdered, new[] { player.playerId });
}
```

Проектируйте сообщения так, чтобы применение полного состояния шло тем же путём в коде, что и применение изменения. [Пример синхронизированного переключателя](/ru/docs/scripting/examples/synced-toggle) делает это с помощью одного байта.

<Callout type="warn">
Не воспроизводите новичку список прошлых событий (например «дверь открыта, дверь закрыта, дверь открыта»). Отправляйте текущий результат. Повторы становятся длинными, приходят устаревшими и ломаются, когда событие зависит от времени.
</Callout>

## Что проверить

- **Работает ли это, если владелец не первый игрок?** Проверьте с тремя клиентами: подключается A, подключается B и что-то меняет, A уходит, подключается C.
- **Задаётся ли что-то в `Start`, что должно приходить из сети?** `Start` у поздно подключившегося выполняется до его первого сетевого сообщения. Показывайте нейтральное состояние, пока не придёт первое сообщение или синхронизированное значение.
- **Постоянные пропы.** Пропам, создаваемым из load config, нужно включить **Persistent**, чтобы они существовали для игроков, которые подключатся позже. Смотрите [Пропы сцены](/ru/docs/world/scene-props).
