참여한 플레이어는 당신이 빌드한 그대로 씬을 로드합니다. 그 이후 바뀐 것(문이 열렸거나, 점수가 올랐거나, 조명이 꺼진 것)은 누군가 알려주기 전까지 그 플레이어에게 보이지 않습니다.

## 동기화 변수: 자동으로 처리됨

`BasisSyncedObject`와 그 위에 만들어진 모든 것(`BasisSyncedParameters`, `BasisSyncedTransform`, `BasisSyncedRigidbody`, `BasisPickupSyncNetworking`)은 플레이어가 참여할 때마다 전체 키프레임을 보냅니다. 소유자가 떠났고 아직 아무도 오브젝트를 소유하지 않은 경우, 상태를 가진 플레이어가 대신 새로 온 사람에게 보냅니다. 아무것도 할 필요가 없습니다.

## 네트워크 이벤트: 상태를 다시 보내기

이벤트는 기억되지 않습니다. 이벤트가 지속되는 상태를 바꿨다면, 그 **상태**(이벤트 기록이 아니라)를 새 플레이어에게 다시 보내세요. 이 일은 소유자만 합니다. 새로 온 사람은 모든 플레이어에게서가 아니라 하나의 메시지만 받습니다.

```csharp title="Native"
public override void OnPlayerJoined(BasisNetworkPlayer player)
{
    if (!IsLocalOwner()) return;
    SendCustomNetworkEvent(PackState(), DeliveryMethod.ReliableOrdered, new[] { player.playerId });
}
```

```csharp title="Cilbox"
void OnPlayerJoined(BasisNetworkPlayer player)
{
    if (!net.HasNetworkID || !net.IsOwnedLocallyOnServer) return;
    net.SendCustomNetworkEvent(PackState(), DeliveryMethod.ReliableOrdered, new[] { player.playerId });
}
```

전체 상태를 적용하는 것과 변경을 적용하는 것이 같은 코드 경로가 되도록 메시지를 설계하세요. [동기화 토글 예제](/ko/docs/scripting/examples/synced-toggle)는 이를 1바이트로 해냅니다.

<Callout type="warn">
새로 온 사람에게 과거 이벤트 목록을 재생하지 마세요(예: "문 열림, 문 닫힘, 문 열림"). 현재 결과를 보내세요. 재생은 길어지고, 오래된 상태로 도착하며, 이벤트가 타이밍에 의존하면 깨집니다.
</Callout>

## 확인할 사항

- 소유자가 첫 번째 플레이어가 아니어도 작동하나요? 세 개의 클라이언트로 테스트하세요. A가 참여하고, B가 참여해서 무언가를 바꾸고, A가 떠나고, C가 참여합니다.
- 네트워크에서 와야 할 것을 `Start`에서 설정하고 있지 않나요? 늦게 참여한 플레이어의 `Start`는 첫 네트워크 메시지보다 먼저 실행됩니다. 첫 메시지나 동기화 값이 도착할 때까지 중립 상태를 보여주세요.
- 영구 소품. 로드 설정에서 스폰된 소품은 나중에 참여하는 플레이어에게도 존재하도록 **Persistent**를 설정해야 합니다. [씬 소품](/ko/docs/world/scene-props)을 참조하세요.
