Cilboxはスクリプトのコンパイル済みコードをサンドボックス内でインタープリター実行します。ほとんどのC#は動作しますが、以下のルールにはほぼ誰もが一度はつまずきます。

## ライフサイクル

- スクリプトに転送されるもの: `Awake`（`Start`の直前に実行）、`Start`、`Update`、`FixedUpdate`、`LateUpdate`、`OnEnable`、`OnDisable`、`OnDestroy`、トリガーとコリジョンのコールバック、`OnRenderObject`と`OnWillRenderObject`。
- `OnGUI`、`OnAnimatorIK`、`OnParticleCollision`、コルーチンは使えません。`Update`と[遅延イベント](/ja/docs/scripting/common-usages#timers-and-delayed-events)を使用してください。
- 最初の`OnEnable`は呼ばれません。セットアップは`Start`で、後片付けは`OnDestroy`で行ってください。
- `BasisNetworkBehaviour`を継承しないでください。スクリプトを置き換えるプロキシは`BasisNetworkBehaviour`ではありません。`SafeUtil.MakeNetworkable(this)`から`BasisNetworkShim`を取得してください（[ネットワークイベント](/ja/docs/scripting/networking/network-events#cilbox)を参照）。

## 構造体は値を共有する

Unityの構造体（`Vector3`、`Quaternion`、`Color`）を変数にコピーすると、同じ値が共有されます。コピー側のフィールドを変更すると元の値も変わります。

```csharp
// Wrong: also moves `target`.
Vector3 p = target;
p.y = 0f;

// Right: build a new value.
Vector3 p = new Vector3(target.x, 0f, target.z);
```

- 配列に対する`points[i].x = 5f`は何も言わずに失われます。`points[i] = new Vector3(5f, points[i].y, points[i].z)`と書いてください。
- `points[i] += offset`は例外を投げます。`points[i] = points[i] + offset`と書いてください。
- Unityの呼び出しや演算子から得られる値（`a + b`、`transform.position`、`new Vector3(...)`）は新しい値なので、変更しても安全です。

## 呼び出しと権限

- ホワイトリストに登録された型は、その型にメソッド制限がない限り、すべてのpublicメソッドが許可されます。フィールドは、記載がない限り拒否されます。
- パラメーター型、ジェネリック型、戻り値の型もチェックされます。名前のチェックを通過しても、いずれかの型が原因で呼び出しが拒否されることがあります。
- `GetComponent`はすべてのサンドボックスで動作します。プロップのサンドボックスでは、ヒエラルキーをたどること（`GetComponentInChildren`、`GetComponentInParent`、`GetComponents`）はブロックされます。
- 別のCilboxスクリプトを見つけるには、`gameObject.GetComponent<OtherScript>()`を呼び出してください。`this.GetComponent<OtherScript>()`はCilboxの型に対してnullを返します。ネイティブコンポーネントはどちらの方法でも動作します。
- `AddComponent`、`SendMessage`、`BroadcastMessage`は常にブロックされます。イベントシムがない場合は`GetComponent`が自動で追加しますが、`BasisNetworkShim`は追加しません。それには`SafeUtil.MakeNetworkable(this)`を使用してください。
- `is`、`as`、キャストは、自分のクラスだけでなくネイティブの型でも、型が完全に一致する場合にのみ一致します。`BoxCollider`に対して`component is Collider`はfalseになるため、具体的な型でテストしてください。
- 配列の配列（`float[][]`、または`a`と`b`が配列である`new[] { a, b }`）は拒否されます。フラットな配列を使い、インデックスは自分で計算してください。
- `[Cilboxable]`クラスの静的初期化子の中で、別のアセンブリの型を指定する`typeof(...)`があると、シーン全体でCilboxの処理が止まります。その場合エディターでは、すべてのスクリプトが目立ったエラーもなくネイティブで実行されるため、他のサンドボックスの問題がすべて隠れてしまいます。
- `Debug.DrawLine`と`Debug.DrawRay`はサンドボックスの`Debug`に存在しません。これらを参照すると、そのコンテンツ内のすべてのスクリプトが読み込まれなくなります。
- 定数は自由に使えます。`const`にはホワイトリストの登録は不要です。

## イベントとデリゲート [#events-and-delegates]

メソッドをデリゲートとして使うたびに新しいラッパーが作られるため、`-=`で追加したものが削除されることはありません。購読は`Start`で一度だけ行ってください。`OnEnable`で購読すると、そのたびに新しいハンドラーが積み重なります。スクリプトより長く存在する発行元については、購読するのではなく`Update`で値をポーリングしてください。

## コンテンツポリス

コンテンツ内のコンポーネントのうち、`[Cilboxable]`でも許可リストに載っているものでもないものは、**読み込み時に破棄されます**。スクリプトの変換とコンポーネントの許可は別々の作業です。[許可されたコンポーネント](/ja/docs/scripting/allowed-components)を参照してください。

スクリプトのフィールドは、宣言された型ではなく、保持しているオブジェクトの型に対してチェックされます。許可されていないコンポーネントを保持する`Behaviour`フィールドはnullになり、要素の型が許可されていない配列フィールドは`Contraband ARRAY`をスローしてそのスクリプトを停止させます。

## アバタースクリプトは全員のマシンで実行される

アバター上のすべてのCilboxスクリプトは、そのアバターを読み込むすべてのクライアントで、アバターごとのビヘイビア上限まで実行されます。装着者専用のロジックは`avatar.IsOwnedLocally`で制限してください（[アバタースクリプティング](/ja/docs/scripting/avatar-scripting)を参照）。

## パフォーマンス

インタープリター実行のコードはネイティブコードよりかなり遅くなります。デスクトップPCでのおおよそのコストは次のとおりです。

| 操作 | コスト |
| --- | --- |
| floatの単純な算術演算 | 約15 ns |
| 自分のメソッドの呼び出し | 約270 ns |
| `Vector3`の演算子（`a + b`） | 約1.7 µs、加えてガベージ |
| `Mathf.Sqrt`などのUnity呼び出し | 約0.9 µs |

スクリプトを軽く保つには、次のようにします。

- 毎フレームではなくイベントで処理してください。タイマー、距離、UIのチェックは1秒に数回で十分です。
- ループ内では`Vector3`の計算よりfloatを優先してください。ホットループ内のベクトル計算は、同じ計算を個別のfloatで行うより約100倍遅くなります。
- 重い処理はコンポーネントに任せてください。Animator、パーティクルシステム、物理、コンストレイントはネイティブで動作します。
- 弾を撃つたびに`Instantiate`を呼ぶのではなく、オブジェクトをプールしてください。
- トランスフォームの処理はまとめて行ってください。`BasisTransformSyncShim`はトランスフォームの配列全体を1回の呼び出しで読み取り、書き込み、コピーでき、`BasisBlendShapeSyncShim`はブレンドシェイプに対して同じことを行います。

<Callout type="info">
**Basis > Tools > Cilbox Permissions**では各サンドボックスのホワイトリストを確認でき、その**Script Check**タブでは、アップロード前にスクリプト内のブロックされる呼び出しをスキャンできます。
</Callout>
