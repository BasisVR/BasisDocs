When content loads, Basis's **content police** removes every component whose type is not on the allowlist for that kind of content. Scripts marked `[Cilboxable]` survive because they are converted to sandboxed proxies first.

## The allowlists

The lists live in `Packages/com.basis.sdk/Settings/`:

| Asset | Applies to |
| --- | --- |
| `SceneContentPoliceSelector` | Worlds |
| `PropContentPoliceSelector` | Props |
| `AvatarContentPoliceSelector` | Avatars |

Each is a list of full type names. Matching is exact: a subclass of an allowed type is **not** allowed unless it is listed itself.

## What is allowed by default

**Worlds and props:** rendering (mesh, skinned mesh, line, trail, particle and LOD components, lights, reflection probes, cameras), physics (colliders, rigidbodies, joints), audio sources and Steam Audio, animators and animation, UI canvases and TextMesh Pro, `VideoPlayer`, VFX Graph binders, AudioLink, Basis constraints, the Basis media player, mirror, seats, pickups, `BasisSyncedTransform`, `BasisPickupSyncNetworking`, `BasisSeatSync`, vehicles, `BasisPlatformSwitch`, and the Cilbox sandbox and shims. Both allow navigation (`NavMeshAgent`, `NavMeshObstacle`). Worlds also allow post processing volumes and the avatar pedestal. The prop list does not include `BasisNetworkShim`. In a prop, add it from code with `SafeUtil.MakeNetworkable(this)`.

**Avatars:** rendering, physics, audio, animators, constraints, seats, synced transforms, OSC, the avatar shims, mirrors, pickups, VFX Graph, and video through the Basis media player, FFUnity and AudioLink's ytdlp player. No cameras, lights, UI or `VideoPlayer`.

**Not allowed by default** (client builds only): `BasisSyncedParameters`, `BasisSyncedRigidbody`, `BasisLocomotionZone`, `BasisRuntimeLoader`, and any native `MonoBehaviour` of your own.

<Callout type="info">
The selector assets are the source of truth and change between versions. Open them in the inspector to see the current list.
</Callout>

## Checking your content

- The **Content Police** section of the Basis Avatar, Prop and Scene inspectors lists what would be removed. Content is only policed when the client loads it, not at build time. Check here before you upload.
- When the client removes a component it logs `Component X is not approved and will be removed`.
- The **Basis > Tools > Cilbox Permissions** window lists what each sandbox lets scripts call.

## Adding a component (client builds)

If you ship your own client, add the type's full name to the matching selector asset. Content built for the public client cannot rely on this; there, convert the logic to a `[Cilboxable]` script.
