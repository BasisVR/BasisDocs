Файл `.bee` (Basis Encrypted Experience) это единый файл, в виде которого поставляется каждый мир, проп и аватар. Он содержит описание контента и по одной сборке Unity на каждую платформу, и всё это зашифровано паролем, который вы задали при сборке.

## Структура

```
┌──────────────────────────────┐
│ Header: connector length     │  8 bytes, little endian Int64
├──────────────────────────────┤
│ Connector (encrypted JSON)   │  metadata, sections table
├──────────────────────────────┤
│ Section 1 (encrypted)        │  e.g. StandaloneWindows64
├──────────────────────────────┤
│ Section 2 (encrypted)        │  e.g. Android
├──────────────────────────────┤
│ ...                          │
└──────────────────────────────┘
```

Секции идут сразу за коннектором одна за другой в том порядке, в котором их перечисляет коннектор. Коннектор хранит длину каждой секции, и этого достаточно, чтобы вычислить, где начинается каждая секция, не сканируя файл.

## Коннектор

Коннектор это JSON-документ (`BasisBundleConnector`), который описывает контент без его загрузки:

| Поле | Содержимое |
| --- | --- |
| `UniqueVersion` | ID сборки. Меняется при каждой сборке. |
| `BasisBundleDescription` | Имя, описание, теги, группа контента и авторство (автор, контакт, лицензия, благодарности). |
| `BasisBundleGenerated[]` | По одной записи на секцию: платформа, режим ассета, имя ассета, CRC, хеш, длина и графические API. |
| `ImageBase64` | Миниатюра, показываемая в меню и на сферах контента. |
| `FarLodBase64` | Только для аватаров: крошечная замена, отображаемая на большом расстоянии. |
| `DateOfCreation` | Время сборки (UTC). |
| `Bounds` | Размер контента. По нему контент размещают до загрузки. |
| `MetaData` | Количество треугольников, материалов и костей, объём памяти текстур, конвейер рендеринга, вид контента (Avatar, Prop или Scene), размещение пропа при создании и количество компонентов каждого типа. |

Поскольку коннектор небольшой и идёт первым, меню могут показывать имена, миниатюры и показатели производительности, скачав только первые несколько килобайт.

## Секции

Каждая запись `BasisBundleGenerated` описывает одну секцию:

| Поле | Значение |
| --- | --- |
| `Platform` | Целевая платформа сборки, например `StandaloneWindows64` или `Android`. `Generic` обозначает запасной вариант на glTF. |
| `AssetMode` | `Scene` для миров, `GameObject` для аватаров и пропов, `GLTF` для универсального запасного варианта. |
| `AssetToLoadName` | Сцена или префаб, который нужно открыть из бандла. |
| `AssetBundleCRC`, `AssetBundleHash` | Проверки целостности расшифрованного бандла Unity. |
| `EndByte` | Длина секции в файле. |
| `AssetBundleEndByte` | Где заканчивается бандл Unity внутри расшифрованной секции, если за ним следуют дополнительные данные. |
| `GraphicsStatePayloads` | Смещения встроенных данных предварительного прогрева шейдеров для каждого графического API и уровня качества. |

Расшифрованная секция это **AssetBundle** Unity, за которым могут следовать данные **graphics state**, используемые для предварительного прогрева шейдеров, чтобы контент не подтормаживал при первом показе.

Секция **Generic** есть только у аватаров: зашифрованный `.glb` (бинарный glTF 2.0) плюс данные настройки аватара. Клиент переходит на неё, только если в файле нет секции для его платформы. Так аватар всё равно отображается на платформах, для которых его никогда не собирали.

## Шифрование

Коннектор и каждая секция шифруются по отдельности паролем контента:

- Шифр: AES с 256-битным ключом.
- Ключ: получается из пароля с помощью PBKDF2 (SHA-1, 10 000 итераций) и случайной 16-байтовой соли.
- Структура каждого зашифрованного блока: `salt (16 bytes) | IV (16 bytes) | ciphertext`.

Секции размером больше нескольких мегабайт расшифровываются параллельными частями. Одна расшифрованная секция может занимать не более примерно 2 ГБ; у файла в целом такого ограничения нет, потому что расшифровывается всегда только одна секция.

<Callout type="warn">
Пароль защищает контент от случайного копирования и позволяет контролировать, кто может его загрузить. Любой, у кого есть URL и пароль, может его расшифровать. Не помещайте секреты в контент.
</Callout>

## Как клиент загружает BEE

1. Читает первые 8 байт (заголовок) HTTP-запросом диапазона.
2. Скачивает и расшифровывает коннектор. Теперь меню могут показать имя, миниатюру и статистику.
3. Проходит по таблице секций, находит секцию для этой платформы и вычисляет её диапазон байтов по длинам.
4. Скачивает только эту секцию запросом диапазона. Секции других платформ так и остаются на сервере.
5. Расшифровывает её, проверяет CRC и загружает AssetBundle (или собирает аватар из glTF).
6. Кеширует файл локально. В следующий раз клиент только проверяет, изменился ли контент.

Именно поэтому один `.bee` может содержать сборки для Windows, Linux и Android, и игрокам на Quest не приходится скачивать объём сборки для ПК.

## Хостинг

- Подходит любой статический хостинг, поддерживающий **HTTP-запросы диапазона**.
- Загрузите `.bee` и поделитесь его URL и паролем. Пароль это то, чем игроки или ваш load config его разблокируют.
- Пересборка создаёт новый `UniqueVersion`, что позволяет клиентам различать сборки. Клиенты перепроверяют закешированные копии на хостинге, и замена файла по тому же URL обновляет его у всех.
