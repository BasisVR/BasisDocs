`.bee`(Basis Encrypted Experience) 파일은 모든 월드, 소품, 아바타가 배포되는 단일 파일입니다. 콘텐츠에 대한 설명과 플랫폼별 Unity 빌드 하나씩을 담고 있으며, 모두 빌드할 때 설정한 비밀번호로 암호화됩니다.

## 구조

```
┌──────────────────────────────┐
│ Header: connector length     │  8 bytes, little endian Int64
├──────────────────────────────┤
│ Connector (encrypted JSON)   │  metadata, sections table
├──────────────────────────────┤
│ Section 1 (encrypted)        │  e.g. StandaloneWindows64
├──────────────────────────────┤
│ Section 2 (encrypted)        │  e.g. Android
├──────────────────────────────┤
│ ...                          │
└──────────────────────────────┘
```

섹션은 커넥터 바로 뒤에 커넥터가 나열한 순서대로 연속해서 이어집니다. 커넥터에는 각 섹션의 길이가 저장되어 있고, 이 길이만으로 파일을 스캔하지 않고도 모든 섹션의 시작 위치를 알 수 있습니다.

## 커넥터

커넥터는 콘텐츠를 로드하지 않고도 콘텐츠를 설명하는 JSON 문서(`BasisBundleConnector`)입니다.

| 필드 | 내용 |
| --- | --- |
| `UniqueVersion` | 빌드 ID. 빌드할 때마다 바뀝니다. |
| `BasisBundleDescription` | 이름, 설명, 태그, 콘텐츠 그룹, 저작 정보(작성자, 연락처, 라이선스, 크레딧). |
| `BasisBundleGenerated[]` | 섹션당 하나의 항목: 플랫폼, 에셋 모드, 에셋 이름, CRC, 해시, 길이, 그래픽 API. |
| `ImageBase64` | 메뉴와 콘텐츠 오브에 표시되는 썸네일. |
| `FarLodBase64` | 아바타 전용: 먼 거리에서 그려지는 아주 작은 대체 모델. |
| `DateOfCreation` | 빌드 시간(UTC). |
| `Bounds` | 콘텐츠의 크기. 로드되기 전에 콘텐츠를 배치하는 데 쓰입니다. |
| `MetaData` | 삼각형, 머티리얼, 본 개수, 텍스처 메모리, 렌더 파이프라인, 콘텐츠 종류(Avatar, Prop 또는 Scene), 소품 스폰 배치, 각 컴포넌트 타입의 개수. |

커넥터는 작고 맨 앞에 오기 때문에, 메뉴는 처음 몇 킬로바이트만 다운로드한 뒤에도 이름, 썸네일, 성능 통계를 보여줄 수 있습니다.

## 섹션

각 `BasisBundleGenerated` 항목은 하나의 섹션을 설명합니다.

| 필드 | 의미 |
| --- | --- |
| `Platform` | `StandaloneWindows64`나 `Android` 같은 빌드 대상. `Generic`은 glTF 폴백을 나타냅니다. |
| `AssetMode` | 월드는 `Scene`, 아바타와 소품은 `GameObject`, 범용 폴백은 `GLTF`. |
| `AssetToLoadName` | 번들에서 열 씬 또는 프리팹. |
| `AssetBundleCRC`, `AssetBundleHash` | 복호화된 Unity 번들의 무결성 검사. |
| `EndByte` | 파일에서 해당 섹션의 길이. |
| `AssetBundleEndByte` | 뒤에 추가 데이터가 있는 경우, 복호화된 섹션 안에서 Unity 번들이 끝나는 위치. |
| `GraphicsStatePayloads` | 그래픽 API와 품질 수준별로 내장된 셰이더 프리웜 데이터의 오프셋. |

복호화된 섹션은 Unity **AssetBundle**이며, 선택적으로 그 뒤에 **그래픽 상태** 데이터가 이어집니다. 이 데이터는 셰이더를 프리웜하여 콘텐츠를 처음 볼 때 끊김이 생기지 않도록 하는 데 사용됩니다.

**Generic** 섹션은 아바타 전용입니다. 암호화된 `.glb`(glTF 2.0 바이너리)와 아바타 설정 데이터로 구성됩니다. 클라이언트는 파일에 자신의 플랫폼용 섹션이 없을 때만 이 섹션을 대신 사용합니다. 그래서 한 번도 빌드하지 않은 플랫폼에서도 아바타가 나타납니다.

## 암호화

커넥터와 각 섹션은 콘텐츠 비밀번호로 각각 따로 암호화됩니다.

- 암호: 256비트 키를 사용하는 AES.
- 키: 비밀번호에서 PBKDF2(SHA-1, 10,000회 반복)와 무작위 16바이트 솔트로 파생됩니다.
- 각 암호화 블록의 구조: `salt (16 bytes) | IV (16 bytes) | ciphertext`.

몇 메가바이트를 넘는 섹션은 병렬 청크로 복호화됩니다. 복호화된 섹션 하나는 최대 약 2 GB까지 가능합니다. 파일 전체에는 이런 제한이 없는데, 한 번에 하나의 섹션만 복호화되기 때문입니다.

<Callout type="warn">
비밀번호는 가벼운 복사로부터 콘텐츠를 보호하고 누가 로드할 수 있는지 제어할 수 있게 해 줍니다. URL과 비밀번호를 가진 사람은 누구나 복호화할 수 있습니다. 콘텐츠에 비밀 정보를 넣지 마세요.
</Callout>

## 클라이언트가 BEE를 로드하는 방법

1. HTTP 범위 요청으로 처음 8바이트(헤더)를 읽습니다.
2. 커넥터를 다운로드하고 복호화합니다. 이제 메뉴에서 이름, 썸네일, 통계를 보여줄 수 있습니다.
3. 섹션 테이블을 순회해 이 플랫폼의 섹션을 찾고, 길이로부터 바이트 범위를 계산합니다.
4. 범위 요청으로 해당 섹션만 다운로드합니다. 다른 플랫폼의 섹션은 서버 밖으로 나가지 않습니다.
5. 복호화하고, CRC를 확인한 뒤 AssetBundle을 로드합니다(또는 glTF로 아바타를 만듭니다).
6. 파일을 로컬에 캐시합니다. 다음에는 클라이언트가 콘텐츠가 바뀌었는지만 확인합니다.

이 덕분에 하나의 `.bee`가 Windows, Linux, Android 빌드를 모두 담으면서도 Quest 플레이어가 PC 빌드의 다운로드 크기를 부담하지 않습니다.

## 호스팅

- 어떤 정적 호스트든 **HTTP 범위 요청**을 지원하면 작동합니다.
- `.bee`를 업로드하고 URL과 비밀번호를 공유하세요. 비밀번호는 플레이어나 로드 설정이 콘텐츠를 여는 데 사용합니다.
- 다시 빌드하면 새 `UniqueVersion`이 생성되어 클라이언트가 빌드를 구별할 수 있습니다. 클라이언트는 캐시된 사본을 호스트와 대조해 다시 확인하고, 같은 URL의 파일을 교체하면 모든 사람에게 업데이트됩니다.
