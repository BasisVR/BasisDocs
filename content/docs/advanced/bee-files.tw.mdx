`.bee`（Basis Encrypted Experience）檔案是每個世界、道具和虛擬形象發佈時所用的單一檔案。它包含內容的描述，以及每個平台各一份的 Unity 建置，全部以您建置時設定的密碼加密。

## 配置

```
┌──────────────────────────────┐
│ Header: connector length     │  8 bytes, little endian Int64
├──────────────────────────────┤
│ Connector (encrypted JSON)   │  metadata, sections table
├──────────────────────────────┤
│ Section 1 (encrypted)        │  e.g. StandaloneWindows64
├──────────────────────────────┤
│ Section 2 (encrypted)        │  e.g. Android
├──────────────────────────────┤
│ ...                          │
└──────────────────────────────┘
```

區段緊接在 connector 之後依序排列，順序與 connector 中列出的相同。每個區段的長度都儲存在 connector 中，因此讀取者不需掃描檔案就能計算出每個區段的起始位置。

## Connector

Connector 是一份 JSON 文件（`BasisBundleConnector`），可在不載入內容的情況下描述內容：

| 欄位 | 內容 |
| --- | --- |
| `UniqueVersion` | 建置 ID。每次建置都會改變。 |
| `BasisBundleDescription` | 名稱、描述、標籤、內容群組和作者資訊（作者、聯絡方式、授權、致謝）。 |
| `BasisBundleGenerated[]` | 每個區段一筆：平台、資產模式、資產名稱、CRC、雜湊、長度和圖形 API。 |
| `ImageBase64` | 在選單和內容球上顯示的縮圖。 |
| `FarLodBase64` | 僅限虛擬形象：在遠距離時繪製的小型替身。 |
| `DateOfCreation` | 建置時間（UTC）。 |
| `Bounds` | 內容的尺寸，以便在載入前就能放置。 |
| `MetaData` | 三角形、材質和骨骼數量、貼圖記憶體、渲染管線、內容種類（Avatar、Prop 或 Scene）、道具生成位置，以及每種元件類型的數量。 |

由於 connector 很小且位於最前面，選單只需下載最前面的幾 KB，就能顯示名稱、縮圖和效能統計。

## 區段

每筆 `BasisBundleGenerated` 項目描述一個區段：

| 欄位 | 意義 |
| --- | --- |
| `Platform` | 建置目標，例如 `StandaloneWindows64` 或 `Android`。`Generic` 表示 glTF 備用版本。 |
| `AssetMode` | 世界為 `Scene`，虛擬形象和道具為 `GameObject`，通用備用版本為 `GLTF`。 |
| `AssetToLoadName` | 要從資源包中開啟的場景或預製件。 |
| `AssetBundleCRC`、`AssetBundleHash` | 解密後 Unity 資源包的完整性檢查。 |
| `EndByte` | 該區段在檔案中的長度。 |
| `AssetBundleEndByte` | 當後面接有額外資料時，Unity 資源包在解密後區段內的結束位置。 |
| `GraphicsStatePayloads` | 依圖形 API 和品質等級嵌入的著色器預熱資料的偏移量。 |

解密後的區段是一個 Unity **AssetBundle**，後面可選擇性地接上**圖形狀態**資料，用於預熱著色器，讓內容第一次被看到時不會卡頓。

**Generic** 區段僅限虛擬形象：一個加密的 `.glb`（glTF 2.0 二進位檔）加上虛擬形象設定資料。只有當檔案中沒有適用於客戶端平台的區段時，客戶端才會使用它，因此虛擬形象在未針對其建置的平台上仍然會出現。

## 加密

Connector 和每個區段都以內容密碼分別加密：

- **加密演算法：** 使用 256 位元金鑰的 AES。
- **金鑰：** 使用 PBKDF2（SHA-1，10,000 次迭代）和隨機的 16 位元組 salt 從密碼衍生。
- **每個加密區塊的配置：** `salt (16 bytes) | IV (16 bytes) | ciphertext`。

超過數 MB 的區段會以平行分塊方式解密。單一解密後的區段最多約為 2 GB；整個檔案則沒有此限制，因為一次只會解密一個區段。

<Callout type="warn">
密碼可保護內容免於被隨手複製，並讓您控制誰能載入它。任何擁有 URL 和密碼的人都能解密它。請勿在內容中放入機密資訊。
</Callout>

## 客戶端如何載入 BEE

1. 以 HTTP 範圍請求**讀取標頭**：最前面的 8 個位元組。
2. **下載並解密 connector。** 選單現在就能顯示名稱、縮圖和統計資料。
3. **走訪區段表**以找出此平台的區段，並根據長度計算其位元組範圍。
4. 以範圍請求**只下載該區段**。其他平台的區段永遠不會被下載。
5. **解密**它、檢查 CRC，然後載入 AssetBundle（或從 glTF 建立虛擬形象）。
6. 將檔案**快取**在本機，讓下次造訪時只需檢查內容是否有變更。

這就是為什麼一個 `.bee` 可以同時攜帶 Windows、Linux 和 Android 的建置，而不會讓 Quest 玩家付出 PC 建置的下載量。

## 託管

- 任何支援 **HTTP 範圍請求**的靜態主機都可以使用。
- 上傳 `.bee` 並分享其 URL 和密碼。玩家或您的載入設定會使用密碼來解鎖它。
- 重新建置會產生新的 `UniqueVersion`，讓客戶端能區分不同的建置。客戶端會向主機重新驗證快取的副本，因此在相同 URL 替換檔案即可更新它。
