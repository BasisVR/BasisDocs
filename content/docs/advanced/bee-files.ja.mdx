`.bee`（Basis Encrypted Experience）ファイルは、すべてのワールド、プロップ、アバターが配布される単一のファイルです。コンテンツの説明と、プラットフォームごとに1つのUnityビルドを含み、すべてがビルド時に設定したパスワードで暗号化されています。

## レイアウト

```
┌──────────────────────────────┐
│ Header: connector length     │  8 bytes, little endian Int64
├──────────────────────────────┤
│ Connector (encrypted JSON)   │  metadata, sections table
├──────────────────────────────┤
│ Section 1 (encrypted)        │  e.g. StandaloneWindows64
├──────────────────────────────┤
│ Section 2 (encrypted)        │  e.g. Android
├──────────────────────────────┤
│ ...                          │
└──────────────────────────────┘
```

セクションはコネクターの後ろに、コネクターに記載された順序で隙間なく続きます。コネクターには各セクションの長さが保存されています。それだけで、ファイルをスキャンせずに各セクションの開始位置がわかります。

## コネクター

コネクターは、コンテンツを読み込まずにその内容を説明するJSONドキュメント（`BasisBundleConnector`）です。

| フィールド | 内容 |
| --- | --- |
| `UniqueVersion` | ビルドID。ビルドのたびに変わります。 |
| `BasisBundleDescription` | 名前、説明、タグ、コンテンツグループ、作者情報（作者、連絡先、ライセンス、クレジット）。 |
| `BasisBundleGenerated[]` | セクションごとに1つのエントリ: プラットフォーム、アセットモード、アセット名、CRC、ハッシュ、長さ、グラフィックスAPI。 |
| `ImageBase64` | メニューやコンテンツオーブに表示されるサムネイル。 |
| `FarLodBase64` | アバターのみ: 遠距離で描画される小さな代替表示。 |
| `DateOfCreation` | ビルド時刻（UTC）。 |
| `Bounds` | コンテンツのサイズ。読み込み前に配置するために使います。 |
| `MetaData` | 三角形、マテリアル、ボーンの数、テクスチャメモリ、レンダーパイプライン、コンテンツの種類（Avatar、Prop、Scene）、プロップのスポーン配置、各コンポーネント型の数。 |

コネクターは小さく先頭にあるため、メニューは最初の数キロバイトをダウンロードしただけで、名前、サムネイル、パフォーマンス統計を表示できます。

## セクション

各`BasisBundleGenerated`エントリは1つのセクションを説明します。

| フィールド | 意味 |
| --- | --- |
| `Platform` | `StandaloneWindows64`や`Android`などのビルドターゲット。`Generic`はglTFのフォールバックを示します。 |
| `AssetMode` | ワールドは`Scene`、アバターとプロップは`GameObject`、汎用フォールバックは`GLTF`。 |
| `AssetToLoadName` | バンドルから開くシーンまたはプレハブ。 |
| `AssetBundleCRC`、`AssetBundleHash` | 復号されたUnityバンドルの整合性チェック。 |
| `EndByte` | ファイル内でのセクションの長さ。 |
| `AssetBundleEndByte` | 後ろに追加データが続く場合の、復号されたセクション内でUnityバンドルが終わる位置。 |
| `GraphicsStatePayloads` | グラフィックスAPIと品質レベルごとの、埋め込まれたシェーダープリウォームデータのオフセット。 |

復号されたセクションはUnityの**AssetBundle**であり、その後ろに任意で**グラフィックスステート**データが続きます。これはシェーダーをプリウォームするために使われ、コンテンツを初めて見たときにカクつかないようにします。

**Generic**セクションはアバター専用です。暗号化された`.glb`（glTF 2.0バイナリ）とアバターのセットアップデータを含みます。クライアントがこれを使うのは、ファイルに自分のプラットフォーム用のセクションがない場合だけです。これにより、一度もビルドしていないプラットフォームでもアバターが表示されます。

## 暗号化

コネクターと各セクションは、コンテンツのパスワードで個別に暗号化されます。

- 暗号方式: 256ビット鍵のAES。
- 鍵: パスワードからPBKDF2（SHA-1、10,000回の反復）とランダムな16バイトのソルトで導出されます。
- 各暗号化ブロックのレイアウト: `salt (16 bytes) | IV (16 bytes) | ciphertext`。

数メガバイトを超えるセクションは、並列のチャンクで復号されます。1つの復号されたセクションは最大で約2 GBです。ファイル全体にはそのような制限はありません。復号されるのは常に1つのセクションだけだからです。

<Callout type="warn">
パスワードはコンテンツを気軽なコピーから守り、誰が読み込めるかを制御できるようにします。URLとパスワードを持っている人なら誰でも復号できます。コンテンツに秘密情報を入れないでください。
</Callout>

## クライアントがBEEを読み込む方法

1. HTTPのレンジリクエストで最初の8バイト（ヘッダー）を読み取ります。
2. コネクターをダウンロードして復号します。これでメニューに名前、サムネイル、統計を表示できます。
3. セクションテーブルをたどってこのプラットフォーム用のセクションを見つけ、長さからそのバイト範囲を割り出します。
4. レンジリクエストでそのセクションだけをダウンロードします。他のプラットフォームのセクションがサーバーから出ることはありません。
5. それを復号し、CRCをチェックして、AssetBundleを読み込みます（またはglTFからアバターを構築します）。
6. ファイルをローカルにキャッシュします。次回、クライアントはコンテンツが変更されたかどうかだけを確認します。

これが、1つの`.bee`にWindows、Linux、Androidのビルドを含めても、QuestのプレイヤーがPCビルドのダウンロードサイズを負担せずに済む理由です。

## ホスティング

- 静的ホストなら、**HTTPレンジリクエスト**に対応していればどれでも使えます。
- `.bee`をアップロードし、そのURLとパスワードを共有します。パスワードは、プレイヤーやロード設定がロックを解除するために使用するものです。
- 再ビルドすると新しい`UniqueVersion`が生成され、クライアントはビルドを区別できます。クライアントはキャッシュされたコピーをホストに対して再検証し、同じURLのファイルを置き換えれば全員のコピーが更新されます。
