`.bee`（Basis Encrypted Experience）文件是每个世界、道具和虚拟形象发布时所用的单一文件。它包含对内容的描述以及每个平台各一个 Unity 构建，全部使用您在构建时设置的密码加密。

## 布局

```
┌──────────────────────────────┐
│ Header: connector length     │  8 bytes, little endian Int64
├──────────────────────────────┤
│ Connector (encrypted JSON)   │  metadata, sections table
├──────────────────────────────┤
│ Section 1 (encrypted)        │  e.g. StandaloneWindows64
├──────────────────────────────┤
│ Section 2 (encrypted)        │  e.g. Android
├──────────────────────────────┤
│ ...                          │
└──────────────────────────────┘
```

各个分段紧接在 connector 之后依次排列，顺序与 connector 中列出的顺序相同。connector 存储了每个分段的长度，据此无需扫描文件就能算出每个分段的起始位置。

## Connector

Connector 是一个 JSON 文档（`BasisBundleConnector`），它在不加载内容的情况下描述内容：

| 字段 | 内容 |
| --- | --- |
| `UniqueVersion` | 构建 ID。每次构建都会变化。 |
| `BasisBundleDescription` | 名称、描述、标签、内容组和作者信息（作者、联系方式、许可证、致谢）。 |
| `BasisBundleGenerated[]` | 每个分段一个条目：平台、资源模式、资源名称、CRC、哈希、长度和图形 API。 |
| `ImageBase64` | 在菜单和内容球上显示的缩略图。 |
| `FarLodBase64` | 仅限虚拟形象：在远距离时绘制的微型替身。 |
| `DateOfCreation` | 构建时间（UTC）。 |
| `Bounds` | 内容的大小，用于在加载之前放置它。 |
| `MetaData` | 三角形、材质和骨骼数量、纹理内存、渲染管线、内容类型（Avatar、Prop 或 Scene）、道具生成位置，以及每种组件类型的数量。 |

由于 connector 很小并且位于最前面，菜单只需下载最前面的几 KB 就能显示名称、缩略图和性能统计。

## 分段

每个 `BasisBundleGenerated` 条目描述一个分段：

| 字段 | 含义 |
| --- | --- |
| `Platform` | 构建目标，例如 `StandaloneWindows64` 或 `Android`。`Generic` 表示 glTF 后备。 |
| `AssetMode` | 世界为 `Scene`，虚拟形象和道具为 `GameObject`，通用后备为 `GLTF`。 |
| `AssetToLoadName` | 要从资源包中打开的场景或预制体。 |
| `AssetBundleCRC`、`AssetBundleHash` | 解密后 Unity 资源包的完整性校验。 |
| `EndByte` | 该分段在文件中的长度。 |
| `AssetBundleEndByte` | 当其后还有额外数据时，Unity 资源包在解密后分段中结束的位置。 |
| `GraphicsStatePayloads` | 按图形 API 和画质等级划分的嵌入式着色器预热数据的偏移量。 |

解密后的分段是一个 Unity **AssetBundle**，其后可以选择附带用于预热着色器的**图形状态**数据，以便内容在第一次被看到时不会卡顿。

**Generic** 分段仅限虚拟形象：一个加密的 `.glb`（glTF 2.0 二进制）以及虚拟形象设置数据。只有当文件中没有适用于客户端平台的分段时，客户端才会退而使用它。这样，虚拟形象在从未为其构建过的平台上也能显示。

## 加密

Connector 和每个分段都使用内容密码分别加密：

- 密码算法：使用 256 位密钥的 AES。
- 密钥：通过 PBKDF2（SHA-1，10,000 次迭代）和随机的 16 字节盐从密码派生。
- 每个加密块的布局：`salt (16 bytes) | IV (16 bytes) | ciphertext`。

超过几 MB 的分段会以并行分块的方式解密。单个解密后的分段最大约为 2 GB；整个文件没有这样的限制，因为每次只会解密一个分段。

<Callout type="warn">
密码可以保护内容免遭随意复制，并让您控制谁可以加载它。任何拥有 URL 和密码的人都可以解密它。不要在内容中放置机密信息。
</Callout>

## 客户端如何加载 BEE

1. 通过 HTTP 范围请求读取最前面的 8 个字节（头部）。
2. 下载并解密 connector。此时菜单已经可以显示名称、缩略图和统计信息。
3. 遍历分段表，找到此平台的分段，并根据长度算出它的字节范围。
4. 通过范围请求只下载该分段。其他平台的分段始终留在服务器上。
5. 解密它，检查 CRC，然后加载 AssetBundle（或从 glTF 构建虚拟形象）。
6. 将文件缓存到本地。下次客户端只需检查内容是否有变化。

这就是为什么一个 `.bee` 可以同时携带 Windows、Linux 和 Android 构建，而不会让 Quest 玩家承担 PC 构建的下载体积。

## 托管

- 任何支持 **HTTP 范围请求**的静态托管服务都可以使用。
- 上传 `.bee` 并分享其 URL 和密码。玩家或您的加载配置需要使用该密码来解锁它。
- 重新构建会生成新的 `UniqueVersion`，让客户端可以区分不同的构建。客户端会向托管方重新验证缓存的副本，在同一 URL 上替换文件后，所有人都会拿到更新。
